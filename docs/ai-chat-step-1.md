# AI 聊天第 1 步：交互范围与接口草案

状态：开发约定草案，供前后端实现和 Leader 确认；本步骤只定义方案，接口和聊天功能尚未实现。

## 本周范围

- 已登录用户在 Dashboard、Company、Order、User 等共享工作台页面可打开悬浮聊天窗口；登录和注册页面暂不显示。
- 打开窗口时加载当前用户最近更新的会话；没有会话时创建一个。关闭窗口不删除会话；刷新后重新加载该会话及消息。页面切换时保留打开状态，刷新后重新打开窗口即可恢复历史。
- 本周以 Qwen 进行真实文字聊天联调。模型请求带有限制的历史上下文；暂定最近 20 条已完成的文本消息（包含本次用户消息），按时间正序传入。具体长度限制在实现时配置并验证。
- 完整回复返回后展示，发送期间显示加载状态；失败时保留用户输入或已保存的用户消息，并提供重试。重试必须针对原消息，避免重复创建用户消息；失败不算 AI 已回答。
- 文本消息支持安全的 Markdown 展示。输入框支持多行、Enter 发送、Shift + Enter 换行。文件提供真实上传及附件记录，模型是否读取文件待确认。
- 导航增加 Agent 任务进度页面，表格明确标注模拟数据。本周不实现意图识别、任务编排或自动执行供应链任务。
- 暂不提供会话列表切换、新建会话按钮或删除功能；后端保留会话接口以支持后续扩展。暂不实现流式输出。

## 数据约定

时间使用带时区的 ISO 8601 字符串；ID 在接口中统一为字符串。会话属于一个已登录用户，消息属于一个会话。所有接口只允许访问当前用户自己的数据。

```json
{
  "id": "session-id",
  "title": "新会话",
  "createdAt": "2026-11-04T12:00:00.000Z",
  "updatedAt": "2026-11-04T12:00:00.000Z"
}
```

```json
{
  "id": "message-id",
  "sessionId": "session-id",
  "role": "user",
  "type": "text",
  "content": { "text": "你好" },
  "status": "completed",
  "createdAt": "2026-11-04T12:00:00.000Z"
}
```

`role` 为 `user` 或 `assistant`；本周实现 `text`，其他类型以后再定义各自的数据结构。用户消息的 `status` 为 `pending`、`completed` 或 `failed`，分别表示等待回答、已成功获得回答、模型调用失败；AI 消息只在成功生成并保存后出现，状态为 `completed`。附件信息独立记录，具体结构待上传方案确认。服务端应保证消息顺序稳定，时间相同时以稳定的次序字段区分。

## 接口草案

以下为 NestJS 路径；浏览器通过 Next.js 服务端代理转发，沿用现有 HttpOnly 会话 Cookie、Bearer JWT 和可信来源检查，不能把模型密钥交给浏览器。接口返回 JSON，不缓存聊天内容。接口列表及格式仍是设计草案，尚未与 Leader 或其他开发者确认。

| 方法与路径 | 请求 | 成功响应 |
| --- | --- | --- |
| `GET /ai-agent/sessions` | 无；按更新时间降序 | `200 { "sessions": [会话] }`，空数组表示尚无会话 |
| `POST /ai-agent/sessions` | `{}` | `201 { "session": 会话 }` |
| `GET /ai-agent/sessions/:id/messages` | 无 | `200 { "messages": [消息] }`，按稳定顺序排列 |
| `POST /ai-agent/sessions/:id/messages` | `{ "text": "你好", "clientRequestId": "客户端生成的唯一 ID" }` | `201 { "userMessage": 消息, "assistantMessage": 消息 }` |
| `POST /ai-agent/sessions/:id/messages/:messageId/retry` | `{}` | `200 { "userMessage": 消息, "assistantMessage": 消息 }`，复用原用户消息 |
| `POST /ai-agent/sessions/:id/attachments` | `multipart/form-data`，字段 `file` | 上传及响应细节待文件规则确认后确定 |

发送请求先校验身份和会话归属，再保存用户消息、读取上下文、调用模型并保存回复。`clientRequestId` 在用户及会话范围内唯一，用于网络重试去重；重复请求不得生成重复用户消息。模型失败时保存失败状态并返回可安全展示的错误及对应 `messageId`，刷新后仍可重试。并发重试同一消息时，服务端只允许一次有效调用；重复发送的具体进行中响应由后端实现时确定并文档化。

常见失败使用 `{ "message": "可展示的错误信息", "code": "ERROR_CODE" }`；模型失败时可附 `messageId`：

- `400`：内容为空或参数不合法；`401`：未登录或登录过期。
- `404`：会话或消息不存在，或不属于当前用户，避免泄露其他用户数据。
- `409`：同一消息正在处理或请求冲突；`413`：请求或文件超出配置限制。
- `502` / `504`：模型服务出错或超时；前端提示失败并允许重试，不展示密钥或上游敏感错误。

上传使用 multipart，现有 JSON 写请求的来源检查不能原样要求 JSON Content-Type；实现时需保留可信来源校验并单独校验 multipart、文件大小和类型。不能把“文件已上传”表述为“模型已理解文件”。
