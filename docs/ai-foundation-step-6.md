# AI 基础能力第六步：四类 Service

本步骤实现 AI 模块内部 Service 和用户隔离，不新增 Controller、HTTP 路由或数据库迁移。参数应先使用第五步 DTO 校验；下一步仍需把 JWT、管理员守卫、DTO 和这些 Service 正确接到接口。

## Service 与分页

- `AiSessionService`：创建、分页、查询、更新状态和软删除会话。新会话在同一事务中创建原聊天会话和 AI 扩展；旧会话没有扩展时读取为 `active`，状态首次更新时按需补建。列表和详情始终按原会话的 `user_id` 与未删除状态筛选。
- `AiMemoryService`：本人记忆创建、分页、按 ID 查询、更新、删除。查询和写操作都限定 `id` 与 `user_id`；内容由数据库的约束和更新时间触发器保护。
- `AiTaskService`：本人任务创建、分页、按 ID 查询、更新、删除；支持按状态筛选。创建只接收任务名称，使用数据库默认状态，更新只接收名称和状态。
- `AiAuditService`：可信服务端创建审计、查询本人审计；管理员可分页查询全部审计或按用户筛选，也可按 ID 查询。支持审计结果与包含边界的 `from` / `to` 时间筛选。Service 不提供审计更新或删除方法，数据库也拒绝这些操作。

分页返回 `{ items, page, pageSize, hasMore }`，按对应时间降序、ID 升序排序；查询多取一条判断是否还有下一页。没有实现总条数统计。

## 权限与调用边界

- 每个方法的 `userId` / `actorId` 必须由后续 Controller 从 `JwtAuthGuard` 验证后的 `request.user.id` 获取，不能取自请求体或让客户端选择。Service 会拒绝缺失或格式无效的用户 ID，避免 ORM 忽略空条件，但 UUID 格式校验本身不是认证。
- 普通用户的读取、更新与删除在数据库条件中同时限定当前用户和记录 ID。记录不存在与不属于当前用户统一返回 404；创建时显式指定允许写入的字段，忽略调用方对象中多余的归属字段。
- 审计全量方法每次从 `users` 表重新确认调用者是 active 管理员；未来路由仍须同时挂载 JWT 与管理员守卫。普通用户审计查询始终限定本人，即使传入多余筛选字段也不放宽范围。
- `AiAuditService.create` 仅供可信服务端内部调用；调用者应在真实操作发生时传入已认证主体，不应将它直接开放给客户端。本步骤未自动为每个操作生成审计记录。

## 会话、锁和缓存边界

会话状态更新使用与现有 `ChatTurnRepository` 相同的 PostgreSQL 咨询锁键；已有对话生成持锁时返回冲突。删除复用旧聊天 Service 的锁和软删除逻辑，保留消息、附件及扩展数据。

`closed` 在本步骤只是 AI 扩展中的状态变更：现有聊天消息/对话接口还没有接入该状态检查，Redis 缓存也尚未实现或清理。是否阻止旧聊天接口向关闭会话发送消息，及关闭时的缓存失效，应在后续接口与缓存集成时明确并验证。

已有 AI 记录的用户可能受到数据库外键 `RESTRICT` 保护而无法硬删除；现有用户管理的错误提示尚未处理该情况，不在本步骤修改范围内。

## 验证

`bknd/test/ai-services.e2e-spec.ts` 使用真实 PostgreSQL 验证四类 Service、分页、按用户隔离、缺失身份时拒绝、会话创建失败回滚、旧会话补建、软删除保留消息、聊天锁冲突、管理员权限实时检查及审计只读。审计测试在事务内运行并回滚，以免留下不可删除的测试记录。使用隔离的临时数据库执行完整后端 E2E；构建、lint 和单元测试也通过。
