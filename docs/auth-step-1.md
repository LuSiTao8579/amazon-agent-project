# 第一步：账号页面与接口范围

## 本次落实的内容

复用现有 ftnd（Next.js / MUI v6）与 bknd（NestJS），不重新初始化项目。
第一步确定路由、最小字段、页面流转和后续接口边界，并提供可浏览的页面原型。

当前状态：**页面框架已建立；注册、登录、表单校验、数据库与认证接口尚未实现。**

## 页面约定

| 地址 | 用途 | 当前行为 | 后续行为 |
| --- | --- | --- | --- |
| / | 网站默认入口 | 跳转 /login | 接入认证后再决定是否按登录状态跳转 |
| /signup | 注册 | 展示禁用的邮箱、密码及提交按钮 | 调用注册 API，成功后提示并进入登录页 |
| /login | 登录 | 展示禁用的邮箱、密码及提交按钮 | 调用登录 API，成功后进入 Dashboard |
| /dashboard | 数据总览 | 无数据的页面框架 | 业务统计与重要变化 |
| /company | 供应链公司 | 无数据的页面框架 | 公司信息及业务状态 |
| /order | 订单追踪 | 无数据的页面框架 | 订单信息及状态 |
| /user | 用户与账户 | 无数据的页面框架 | 按后续任务实现账户或用户管理 |

当前四个业务入口**允许公开预览**，这是开发原型，不是已经完成登录保护的产品。
页面上的“查看 Dashboard 页面框架（非登录）”只用于浏览，不代表认证成功。
预览中的导航由统一配置生成，后续再升级为正式共享布局。

## 已选定的最小交互方案

1. 用户填写邮箱和密码，提交注册请求。
2. **仅当真实注册 API 返回成功**，才展示注册成功提示并进入 /login。
3. 用户在 /login 使用邮箱和密码登录。
4. **仅当真实登录 API 返回成功**，才建立登录状态并进入 /dashboard。
5. 请求失败留在当前页并显示对应错误，不误报成功。

本步骤只约定以上流程；不会模拟 API 成功、自动签发测试 Token 或存储登录状态。
注册后不自动登录。暂不增加确认密码、忘记密码、记住我、邮件验证码和第三方登录。

## 后续接口约定草案（尚未新增 API）

后端继续使用本地 NestJS 服务；以下是建议约定，不代表接口已可调用。

| 方法与路径 | 输入 | 计划结果 |
| --- | --- | --- |
| POST /auth/signup | JSON：email、password | 201 创建用户；400 输入不合法；409 邮箱重复 |
| POST /auth/login | JSON：email、password | 200 认证成功；400 输入不合法；401 认证失败 |
| GET /auth/me | 后续约定的登录凭证 | 200 当前用户；401 凭证缺失或失效 |

现有 /auth/me 仅验证本地测试 JWT，不是用户数据库查询接口，后续需要升级。
本步骤不创建接口响应类型或调用代码；精确响应 JSON、JWT 传递/存储方式及退出登录方案，在后端实现前统一。
密码不能写进 URL、日志或前端持久化存储；API 不返回明文密码或密码哈希。

## 校验范围与待确认事项

- 邮箱、密码空值和邮箱格式：前后端均需校验；MUI 负责展示错误，业务校验需要代码实现。
- 邮箱重复、用户不存在、密码错误：由后端判断，前端呈现真实结果。
- 密码长度、最大长度与具体规则尚待统一，不把特殊符号一概当成非法字符，也不静默裁剪密码。
- “邮箱不存在”与“密码错误”是否分别提示需确认；建议对外统一提示，减少账号枚举风险。
- 四个业务页面本次先做入口和框架；图表、公司/订单 CRUD、用户管理 CRUD 与 AI 不在本步骤范围内。

## 文件阅读顺序

1. 本文：先了解现在做了什么、没做什么。

6. ftnd/src/app/dashboard、company、order、user 下的 page.tsx：各自选择对应页面配置。
7. ftnd/src/app/page.tsx：默认入口跳到登录页；不是登录成功跳转。
8. ftnd/src/app/layout.tsx：网站全局标题和原有 MUI Provider。

## 本步骤验收

在 ftnd 执行 npm run dev，打开 http://127.0.0.1:3000：

- 根路径跳转 /login，注册与登录页面可以相互切换。
- 邮箱、密码和提交按钮均禁用，说明文案清楚，没有“注册成功”或“登录成功”的模拟结果。
- 通过明确标注的预览链接进入 Dashboard，四个入口均可切换、直接访问和刷新。
- 各页面显示对应标题与占位说明，不展示假用户、假统计数据。
- 页面不向后端发送注册登录请求，也不写入 Token、Cookie 或 localStorage 登录状态。
- 运行 npm run lint、npm run typecheck、npm run build 检查工程。
