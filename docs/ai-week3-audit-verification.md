# 第三周第五步 · 工具审计完整性与脱敏验收

在隔离 PostgreSQL、Redis 和真实 Nest HTTP 入口上，9 个请求触发 6 次工具调度。逐次回读得到 6 条已提交的工具审计，2 条成功、4 条失败。审计表原始行和审计 API 输出中，合成敏感标记明文检出数均为 0。[验收脚本](../bknd/scripts/verify-ai-tool-audits.mjs)

## 逐次对账

每个请求先记录全库审计 ID 和管理员列表 ID，再调用聊天接口并核对两个集合的增量。测试同时统计注册中心和公司 Service 的真实方法调用次数。模型提案固定，业务异常用例让公司 Service 单次抛出带合成标记的异常。账号、会话、权限检查、缓存和审计写入均使用应用的实际实现。

| 聊天请求 | 聊天结果或 HTTP 状态 | 注册中心次数 | 预期审计 | 数据库新增 | API 新增 |
| --- | --- | ---: | ---: | ---: | ---: |
| 正常公司查询 | OK | 1 | 1 | 1 | 1 |
| 同条件、新 requestId，命中缓存 | OK | 1 | 1 | 1 | 1 |
| 同一已完成 requestId 重试 | 原回合、原消息 | 0 | 0 | 0 | 0 |
| 普通用户查用户列表 | FORBIDDEN | 1 | 1 | 1 | 1 |
| 禁用工具后再次查同一批公司 | TOOL_UNAVAILABLE | 1 | 1 | 1 | 1 |
| 提案含非法嵌套参数 | INVALID_ARGUMENTS | 1 | 1 | 1 | 1 |
| 公司 Service 抛错 | EXECUTION_FAILED | 1 | 1 | 1 | 1 |
| 未带 JWT | HTTP 401 | 0 | 0 | 0 | 0 |
| 无效 JWT | HTTP 401 | 0 | 0 | 0 | 0 |

首次查询和缓存命中均返回同一家公司，本页 1 行、匹配总数 2。公司 Service 的增量分别为 1 和 0。审计装饰器包住注册中心的执行入口，缓存读取在工具内部；两次独立调度各写一条。重试由聊天服务根据会话和 requestId 找到原回合，直接返回已保存的消息。JWT 被拒时，请求在 HTTP 守卫处结束。[审计装饰器](../bknd/src/ai/tools/audit-tool-execution.decorator.ts) · [聊天回合](../bknd/src/ai-agent/chat-turn.service.ts)

## 字段、可见范围与脱敏

- 每条记录核对执行人、权限动作、工具名、资源类型、结果状态和时间。时间位于调用前后读取的数据库时钟之间。IP 对应本地 HTTP 连接对端，测试传入的转发头未覆盖它。
- 成功表格的摘要精确包含 code、resultType、returnedCount 和 total；失败摘要精确包含 code 和 resultType。通过对整个对象的相等性检查，可发现额外写入的结果行或异常信息。
- 以两个普通账号核对本人列表与相互读取详情时的 404。普通账号访问管理员列表得到 403。管理员按用户筛出全部 6 条，再加窄时间范围，仅返回指定的权限拒绝记录。
- 扫描合成密码、令牌、嵌套内容、自由文本、动态字段名、搜索词、公司结果字段及内部异常文本。检查覆盖数据库整行、管理员列表与详情、本人列表与详情。参数在写库前生成脱敏副本。字段名采用固定清单，未知键只留下位置标签，整个值写为 `[REDACTED]`。业务工具继续使用原始参数。[脱敏实现](../bknd/src/ai/tools/tool-audit-data.ts) · [单元回归](../bknd/src/ai/tools/tool-audit-data.spec.ts)

## 在仓库根目录复跑

```sh
bash bknd/scripts/verify-ai-foundation.sh
```

脚本启动临时 PostgreSQL 和 Redis，在升级测试库中运行逐次对账，并在全新迁移库运行全量测试，退出时清理两个容器。
